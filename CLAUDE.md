# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

ElektoImapPosh is a PowerShell module that reads email by IMAP from several accounts, Gmail and Google Workspace first. It is the reading companion of ElektoMailPosh (github.com/elekto-com-br/ElektoMailPosh), which only sends. That repository sets the standard here: structure, coding and comment style, README sections, CI, release process. Read its counterpart before writing something new. The repository is public from its first commit, and this file is part of it: it keeps the decisions taken and their reasons, what was measured, and the plan, so that the work goes on the same way on any machine and with anyone.

## Commands

- `./Build.ps1`: restores MailKitLite and MimeKitLite into `lib/` (needs the .NET SDK 10), parses every script, validates the manifest, runs PSScriptAnalyzer and Pester when installed, stages `out/ElektoImapPosh` (a single merged `.psm1` plus `lib`) and imports it in a clean process. Run it once before importing from the source: without `lib/` the module refuses to load. `-SkipTests` skips Pester; `-ExpectedVersion` is for the publish workflow. The tests run in a `pwsh` of their own with `IMAP_CONFIG_DIR`, and `HOME` on Linux and macOS, in a temporary folder (in the build's own process `$HOME`, which the module goes by, was fixed at its start), and the build fails if the accounts of the machine changed or a test left accounts in that folder (`Get-AccountState`: the files of the account folders, and on Windows the credentials `ElektoImapPosh:*` listed by `CredEnumerate`, by name, size and time, never by what they hold), as ElektoMailPosh's build does since its #19.
- One test file or one test, in a fresh process, since the module loads assemblies that cannot be unloaded: `pwsh -NoProfile -Command "Invoke-Pester ./Tests/Module.Tests.ps1 -Output Detailed"`, adding `-FullNameFilter '*refuses*'` for a single test. CI pins Pester 6.2.0 and PSScriptAnalyzer 1.25.0.
- `./Tests/Container/Invoke-ContainerBuild.ps1`: runs `Build.ps1` in a container (Podman or Docker), as ElektoMailPosh's does: an image of Ubuntu 24.04 with PowerShell, the .NET SDK, Pester, PSScriptAnalyzer, smtp4dev and the mail libraries restored at its build (the only step with network), then a run without network (the tests start smtp4dev on the loopback, which stays), as a user that is not root, with the repository mounted read-only and copied inside. Nothing of the machine but the repository reaches the tests (not its accounts, passwords or `IMAP_*` variables), so the tests that write accounts and passwords run there rather than on a machine with real accounts.
- After a change made on purpose to the parameters of a public command: `./Tests/Get-PublicInterface.ps1 | Set-Content ./Tests/PublicInterface.txt`, committed with the change (`PublicInterface.Tests.ps1` fails until then).
- Updating the mail libraries: change the versions in `Dependencies/Dependencies.csproj`, run `dotnet restore Dependencies --force-evaluate` to rewrite `packages.lock.json`, and commit both. The build restores with `--locked-mode`. Dependabot proposes these updates, grouped.

## Conventions

- Code, comments, docs and commit messages are in English. Comments say why, in full sentences, as the code around them does; a claim that was measured says so ("measured"), and a fix that came from a review names it ("Copilot on #13").
- Source files are ASCII, with CRLF in the working tree (`core.autocrlf` is on; the index keeps LF). A character outside ASCII goes in as an escape (`` "`u{F3}" `` in a PowerShell string, a regex escape in a regex) or is built (`[char]0x131`).
- Editing with Claude Code: a backslash, a `u` and four hex digits in the input of a tool have arrived as the character itself, and a doubled backslash before a `u` as a single one. Text with such escapes is copied from the file it lives in, or built by concatenation, rather than typed again, and the files are checked afterwards: no byte above 127 (`grep -P '[^\x00-\x7F]'` finds none), and as many of those escapes as before. Python that edits files goes in a file written by the Write tool, not in a Bash heredoc, which changes backslashes. What worked for a pattern full of escapes (2026-11-06): each escape typed as the placeholder `\U{XXXX}` (a capital U and braces, which no tool turns), then a script in the scratchpad that turns the placeholders into escapes, building the backslash with `chr(92)` and reading and writing bytes, so CRLF stays; to edit a line that already has escapes, the same script the other way first. That day a doubled backslash before a `u` stayed doubled in the Write tool, and arrived single in Bash.
- Scale: a mailbox has hundreds of thousands of messages and Gmail hundreds of labels, so no scan of a list inside a loop over messages, folders or labels; index once (hashtable, `HashSet`, `Dictionary`), and sort big arrays with `[Array]::Sort`, not `Sort-Object`. Measured in PowerShell 7.6: a `Where-Object` predicate costs about 4 us and a function call 20 to 80 us; `Sort-Object` of 300,000 UIDs 1.6 s against 0.04 s; the labels of 200 messages against 500 folders 5.3 s before the index (`Get-PolicyFolderSet`), 0.3 ms per message after. A test compares the check on 10 and 1000 folders by ratio, which a slow CI does not fail. A cache is measured after it is filled: the one search of 1000 folders that `Find-ImapFolder` then keeps took 40 ms on a slow runner, and failed the ratio on the CI of 9f9418d. Measure with realistic sizes before proposing a commit (the rule since #12, where Copilot found a `Where-Object` over all the summaries for each UID).
- Mutation testing: before a commit, each part of a change is undone in a copy of the module and the tests run there; a part that no test catches gets a test, or the reason no test can catch it goes in the pull request, whose description says how many mutations ran.
- Environment variables in the tests: clear one with `Remove-Item -LiteralPath "env:$name" -ErrorAction Ignore`, and put one back with `Set-Item -LiteralPath "env:$name" -Value $saved`, which removes it when `$saved` is `$null`. Since .NET 9, `[Environment]::SetEnvironmentVariable($name, $null)`, which PowerShell passes as `""`, leaves the variable defined and empty, and so do `$env:NAME = ''` and `Set-Item -Value ''` (measured on PowerShell 7.6; found by the ElektoMailPosh session): the whole suite left 42 `IMAP_*` variables behind, empty, in its process. The module takes an empty variable for none, so no test failed. A test of `Tests/Module.Tests.ps1` keeps `SetEnvironmentVariable` out of the test scripts.

## Architecture

- `ElektoImapPosh.psm1` loads `lib/MimeKitLite.dll` and `lib/MailKitLite.dll`, then dot-sources `Private/*.ps1` and `Public/*.ps1` inside `#region Functions`. `Build.ps1` replaces that region with the functions themselves in the package, so keep the marker.
- The full MailKit and MimeKit have the same namespaces as the Lite ones, and a type literal resolves to whichever assembly was loaded first (tested). The import therefore stops when the full ones are already in the session (Mailozaurr loads them) or when another file version of a Lite one is. In exchange, the code uses plain literals such as `[MailKit.Net.Imap.ImapClient]`.
- `Dependencies/` is a project that is only restored, never built: it exists for Dependabot and for the NuGet audit (`NuGetAuditMode` all, NU1901 to NU1904 as errors), which fails the build on a known vulnerability.
- Each public command is a `Public/<Name>.ps1` listed in `FunctionsToExport`. `Tests/Module.Tests.ps1` checks that the exports match the manifest and that each command has a synopsis, a description, examples and every parameter documented.
- Errors (`Private/Errors.ps1`): a failure the user must see is reported once, through `Write-ImapError $Cmdlet ...` (the public command passes its `$PSCmdlet` to the helpers), with an ErrorId and a category, and the helper returns `$null` or `$false`. Never throw and catch it on the way: PowerShell adds each exception caught to `$Error` and to `-ErrorVariable`, and one failure read as five (measured). A configuration that cannot be read (accounts.json, `IMAP_PORT`) is still thrown.
- An exception of .NET (a method call that throws) ends only its own statement, unless a try/catch or `$ErrorActionPreference = 'Stop'` is up the stack: the function and its caller go on. So `Write-AccountFile`, `Save-StoredPassword` and `Clear-StoredPassword` set `$ErrorActionPreference = 'Stop'`, and a failure there stops `Set-ImapAccount` and `Remove-ImapAccount` before a password and the file stop matching (#23, found on ElektoMailPosh's copy of this code: a password file that could not be deleted was reported deleted, and its account removed). The password file is deleted by `[IO.File]::Delete`, as the Credential Manager deletes, so that the test on Linux covers the stop that Windows relies on. Such a test runs the command in a process of its own (`Invoke-AsUserScript` in `Tests/Accounts.Tests.ps1`, with `-OutputFormat text`): Pester runs each test inside a try/catch, inside which the exception stops the command with the fix or without it, and a child `pwsh` given a script block answers in XML, which stops it too (both measured there); then the test checks what the command did before it stopped (the account kept, the password not stored). Reading a password has no such stop: `Get-ImapAccount` catches what it throws, and a command that reads, left without the password, connects to nothing (it then reports `PasswordMissing` after the real error, measured).
- MailKit operations run by their `...Async` methods through `Wait-ImapTask`, which returns the failure message instead of throwing and waits in 200 ms steps, so Ctrl+C (a pipeline stop) ends the command at once; the command's `finally` disposes of the client. A synchronous `Connect` held a stopped pipeline for 120 s (the test "stops at once on Ctrl+C" catches that).
- Ctrl+C stops the wait, not the task, so a task that changes files must not go on after the command ends (Copilot's ninth review on #13: the write of an attachment renamed its file after the command had ended, with `-Force` over the one there, reproduced). The write renames only once it takes a `TaskCompletionSource` (`$commit`), which the command, stopped, takes first in a `finally`; when the task took it first, the command waits for it. A `finally` entered by Ctrl+C runs to its end, .NET waits and the loop of `Wait-ImapTask` included, and `Stop()` returns after it; PowerShell notices Ctrl+C in a loop and at the call of a function or cmdlet, not at an assignment (all measured).
- Ending a connection: `Disconnect-ImapClient` logs out for 2 s at most (`LogoutTimeout`) and disposes in a `finally`; with `-Abort` it only disposes. A command passes `-Abort` unless it got to its end, by a flag set after its last output (`$ended` in `Test-ImapAccount`, `$answered` in `Connect-ImapClient`), never by `$PSCmdlet.Stopping`: after Ctrl+C down the pipeline (the command waiting in its own output), its `finally` runs with `Stopping` still false and is not interrupted (tested). While a login waits, MailKit refuses any other command ("busy"), so no LOGOUT can go out then. Tests: `Start-FakeImapServer` in `Tests/Connection.Tests.ps1`, a fake server that stays silent at LOGIN or LOGOUT.
- `IMailFolder` is `IEnumerable<MimeMessage>`: a folder written to the pipeline (returned from a function without `,$folder`) is enumerated, downloading every message, or failing when it is not open. `ImapClient` is not enumerable. Helpers return folders in an array (`return , $folders`, as `Private/Folders.ps1` does); piping an array of folders to `Where-Object` is safe. A list returned so is one object to a pipeline that starts with the call: `Get-ImapPartList ... | Where-Object { $_.Withheld }` got the whole list, whose properties were those of every part, so a message with two programs attached was refused for its "inline part 'tool.exe setup.exe'" (a test caught it); assign it first (`$parts = Get-ImapPartList ...`).
- Connections (`Get-ImapSession` and `Close-ImapSession` in `Private/Connection.ps1`): a command that reads keeps a hashtable of sessions from `begin`, opens one per account the first time `process` needs it (a failure is reported once, then that account is skipped), logs out in `end`, and only disposes in `clean`, which runs after Ctrl+C or a terminating error. `Resolve-ImapAccountName` expands `-Account` (wildcards, names as given, `''` for the default account or the `IMAP_*` variables). A session is kept under the name given and under the account's name, so `''` and the name of the default account share one connection and one count of `MaxMessages` (Copilot on #11), and `Close-ImapSession` closes it once.
- A name from the pipeline is literal: `Folder` piped from `Get-ImapFolder` (later `Get-ImapMessage`) is the exact full name of a folder the server listed, while a typed `-Folder` may be a special use, a name ignoring case or a pattern. On Gmail a label `Sent` would otherwise become the sent folder, and `Read-ImapMessage` would read another message with the same UID. The command tells them apart in `begin`, where `$PSBoundParameters` holds only what was typed and a typed parameter is never replaced by the pipeline (tested): `$folderFromPipeline = -not $PSBoundParameters.ContainsKey('Folder')`, then `Select-ImapFolder -Literal`.
- Output objects carry a `PSTypeName` (`ElektoImapPosh.Folder`), with a table view in `ElektoImapPosh.Format.ps1xml`: five properties or more would show as a list. The folder's full name is the property `Folder`, not `Name`, so it binds to `-Folder` of the next command, while `-Account` takes the alias `Name` from `Get-ImapAccount`.
- PowerShell gotcha with MailKit 4: `$folder.Fetch(0, -1, [MailKit.MessageSummaryItems]'...')` binds the `IFetchRequest` overload and fails. Pass `[MailKit.FetchRequest]::new($items)`.
- PowerShell gotcha with MimeKit: `[MimeKit.HeaderId]::Subject` fails ("differs only in letter casing", since the enum has both `Autosubmitted` and `AutoSubmitted`). Cast a name instead (`[MimeKit.HeaderId]'Subject'`) or find a header by its `Field`. `MimeKit.Cryptography.AuthenticationResults` is in MimeKitLite (`TryParse` on a header's `RawValue`, tested with a Gmail header).
- MailKit's `FetchAsync` may return summaries of messages not asked for, when another client changes the folder (its documentation says so): `Get-ImapMessageSummary` keeps only the UIDs asked for (Copilot on #11). The day of `MaxAgeDays` is `InternalDate.Date`, the day as the server keeps it, which IMAP's SINCE compares, not `LocalDateTime`.
- PowerShell gotcha with expression trees: `$E::New(...)` on `[System.Linq.Expressions.Expression]` is read as its constructor (`::new`, in any case), not as the factory `Expression.New`; call a static method instead (`File.Open` in `$script:SaveFileTask`). Code that runs on the thread of a task or of MailKit (the certificate callback, the write of an attachment) is such a delegate, since a script block has no runspace there.
- PowerShell unwraps a `Nullable`: MailKit's `InternalDate` (`DateTimeOffset?`) and a `[Nullable[datetime]]` parameter arrive as the value itself, so `.Value` is `$null`; use `.LocalDateTime`, `.Date` directly.
- MailKit sends `X-GM-RAW` as an atom when the search has no space (`X-GM-RAW has:attachment`), quoted otherwise. A label `NIL` in X-GM-LABELS is a label named "NIL" (MailKit issue #244), which MailKit returns as that text: keep it.
- Gmail's categories (Primary, Social, Promotions, Updates, Forums, Purchases, Reservations) are no folders nor labels to IMAP: the raw X-GM-LABELS of their messages never names them, but `X-GM-RAW "category:promotions"` finds them, and so does `SEARCH X-GM-LABELS` by undocumented names, `^smartlabel_promo` (`_personal`, `_social`, `_notification`, `_group`) with the counts of `category:`, and `^sq_ig_i_promo` and the like with fewer, it seems those of the category still in the inbox (all measured on a real Gmail, 2026-11-07; MailMate's author and others write the same). Decided with JP: no policy by category, a guess of Gmail's, and `-Query` stays free; the README says how to search them, among Gmail's quirks. Gmail's `has:attachment` counts images shown in a body, and on a real mailbox most of its results had images only shown in their body, which `HasAttachments` does not: also in the README.
- MimeKitLite has no `HtmlToText` (only `HtmlTokenizer`, `HtmlToHtml`, `TextToHtml`, `FlowedToText`, `TextToText`), and converting HTML to text is out of the scope of the module: an agent reads HTML as it is, and an automation searches the body by regex; whoever wants plain text pipes the HTML to a converter of its own. MimeKit already decodes what matters (`TextPart.Text`: the transfer encoding, base64 or quoted-printable, and the charset; headers by RFC 2047; `MimePart.Content.DecodeTo` for attachments).

## Text and culture

- PowerShell compares strings linguistically: `-eq` and `-ceq` (so `Should -Be` and `-BeExactly`) take a name and its decomposed form (NFD) for equal, so tests of normalization compare with `[string]::Equals($a, $b, 'Ordinal')`. They, and `-contains`, also ignore format characters: `'client.example' -eq "cli<U+202E>ent.example"` is true, and so with a soft hyphen or a zero-width space (measured; the keys of a hashtable do not). So the names a policy goes by that a sender can write (a domain, the receiving server) are compared by `Test-SameText` (both composed, then `OrdinalIgnoreCase`), and a domain within another by `Test-WithinDomain`, alike; before it, a domain with an override of direction passed for another in the check of a relay, found by a test of `Format-ShownText`, and harmless there only because each path still needs a real authentication of the domain.
- It also ignores case as the culture of the thread does, and in Turkish `I` is not the capital of `i`: in a session in tr-TR, `'X@CLIENT.EXAMPLE' -like '*@client.example'` is false, so a deny list of senders let the sender through, `-like` missed `INVOICE.ZIP` for `*.zip`, and `'conin$' -match '^CONIN\$'` is false (all measured). Measured in tr-TR: `-like`, `-match`, `-replace`, `-split`, `switch -Wildcard` and `-Regex`, `Where-Object -Like`, `Select-String`, `Sort-Object -Unique`, `Group-Object`, `ToLower()`, `CurrentCultureIgnoreCase` and `ValidatePattern` without `Options` change with the culture; `-eq`, `-in`, `-contains`, the keys of a hashtable, a plain `switch`, `ValidateSet` and `OrdinalIgnoreCase` do not.
- `WildcardPattern` (under `-like`) compares a pattern without wildcards, or with only a `*` at its end, as the culture does, which takes NFC and NFD for one (`string.Equals`, `StartsWith`), and any other pattern character by character, so a pattern with a wildcard before an accented letter misses a name written decomposed, as macOS writes names (measured).
- So `Private/Text.ps1` holds the only ways of comparing text that the culture changes. Every match of a pattern goes through `Test-Wildcard` (`IgnoreCase, CultureInvariant`, with the text and the pattern composed by `ConvertTo-ComposedText`, some 20 us more a match, measured), and every check of a pattern through `Assert-WildcardPattern` (which keeps the message of `-like` itself, since a method of .NET would wrap it in 'Exception calling "IsMatch"', and checks the pattern composed, as `Test-Wildcard` matches it: a range whose end composing changes, U+232A being U+3009 composed, passed a check of the pattern as written and failed when applied, Copilot on #14). Elsewhere the module uses only `-cmatch`, `-creplace` and `-csplit`, with patterns that name both cases, `[regex]::IsMatch(..., 'IgnoreCase, CultureInvariant')` (the device names of Windows), and `ValidatePattern` with `Options = 'None'`. `Tests/Text.Tests.ps1` parses the code of the module and fails on any other form outside `Private/Text.ps1`; a second test feeds it each of those forms, so that it cannot pass by finding nothing.
- Text from a message, as the module returns and shows it, also goes through `Private/Text.ps1`: the sender writes it, and can put in it an escape sequence (it clears the screen, and OSC 52 writes the clipboard: PowerShell passes escape sequences to the terminal), an override of direction (`fdp.exe` shown as `exe.pdf`), text that an AI reads and a person does not see (the tags of Unicode, U+E0000 to U+E007F; variation selectors in a row), and enough of it to flood the context of an AI. `Format-ShownText` (one line: the subject, each address, the Message-IDs, the name of an attachment, the addresses in a reason of the policy) removes the characters that only change how a text is shown (`$script:InvisibleCharacter`: soft hyphen, zero-width space, word joiner, BOM, and the marks of direction ALM, LRM, RLM, which can turn the digits of an amount around), shows each run of the hidden ones (`$script:HiddenCharacter`: Cc and Cf, but for ZWNJ and ZWJ, which emoji and Persian need; the Cf outside the BMP, which a pattern of .NET sees as two halves, named one by one; a half of a character alone; two or more variation selectors) as one U+FFFD, a tab or line break as a space, and cuts it to 1000 characters ending in U+2026; `Format-ImapAddress` keeps the first 100 addresses of a list, then `... and N more` (decided with JP, 2026-11-06: a script that answers everyone fails on that entry, rather than leave people out unsaid). `Format-ShownBody` does the same to the text of a message, keeping its tabs and line breaks, never cut (decided with JP: it removes nothing a reader sees, so it is no redaction). `Get-AttachmentFileName` takes the same characters out of a name, with `_` for the hidden ones. A test walks every code point that .NET knows (in C#, since a loop of 1.1 million in PowerShell took 20 s) and checks that the hidden ones are all taken and nothing else is touched. Cost, measured on 1,000 summaries: `ConvertTo-ImapMessage` from 120 to some 390 us a message (at the default `-First 50`, 14 ms more), almost all of it the calls (a function with a typed parameter costs some 40 us, an untyped one 20 us, and even the one look at clean texts, a join and an `IsMatch`, 29 us), so `Format-ShownText` takes several texts in one call and looks at them all at once before doing anything. MailKit drops from an envelope an address with a control character in it, and keeps one with an override of direction (measured).
- PowerShell keeps the regexes it built (for `-match` and for `ValidatePattern`) with the culture they were built in, so a test of a regex in Turkish runs in a process that starts in it: `Tests/Text.Tests.ps1` calls `[Environment]::ProcessPath` with a script block, whose output comes back as objects. A test of a match by pattern sets the culture of the thread, and puts it back in a `finally`.

## Design decisions (ask before revisiting)

- PowerShell 7.6 or later and the `net10.0` assemblies: .NET 8 is out of support.
- Read-only by construction, since Gmail has no read-only IMAP credential: folders opened with `FolderAccess.ReadOnly` (EXAMINE) and bodies fetched with BODY.PEEK (what MailKit uses), so reading never sets `\Seen`. Commands that write come in a later phase, with ShouldProcess and ConfirmImpact as in ElektoMailPosh's `Remove-MailAccount`. Never delete; at most, move to the trash.
- Writing needs the account's permission, for each kind of change: the setting `AllowWrite` of an account (`Set-ImapAccount -AllowWrite Flags, Move`; the kinds are `Flags`, `Move`, `Labels`, or `All`, which includes those of later versions, or `None`, the default), or `IMAP_ALLOW_WRITE` without accounts (`Flags,Move`, or `true` for all). In accounts.json a list, with `true` and `false` read as all and none. It stays a setting of the account, not of a policy, so writing stays off unless allowed. Without it the module only reads: every command that changes the mailbox calls `Test-ImapWriteAllowed` with its kind of change first (or `Open-ImapFolder -ForWrite <kind>`), whatever it changes, and refuses with `WriteNotAllowed`; besides, folders are opened read-only (EXAMINE), so the server refuses changes to their messages and nothing is marked as read. EXAMINE covers only the folder opened, not the connection: COPY to another folder, CREATE, RENAME, DELETE and APPEND still work, hence the check in our code (Copilot on #5). Done in #5, by kind in #9.
- Accounts are not shared with ElektoMailPosh, each tool with its own app password: `accounts.json` in `IMAP_CONFIG_DIR`, or else in `ElektoImapPosh` under `%APPDATA%` (`~/.config` elsewhere), read ignoring case. Passwords come from `IMAP_PASS_<ACCOUNT>` first, then the Windows Credential Manager (generic credential `ElektoImapPosh:<account>`) or an owner-only file `secrets/<account>` on Linux and macOS, adapted from ElektoMailPosh's `Private/Accounts.ps1` and `Private/PasswordStore.ps1`. Never read the `ElektoMailPosh:<account>` credential. `accounts.json` is written beside itself and renamed into place (#4); when it is a link, as GNU stow makes one into a dotfiles repository, the file it finally points to is the one written (`[IO.File]::ResolveLinkTarget($path, $true)`), since the rename over the link would put a regular file in its place and leave the file in the repository behind (#22, found on ElektoMailPosh).
- Without accounts: `IMAP_USER` and `IMAP_PASS` (required), `IMAP_SERVER` and `IMAP_PORT` (default `imap.gmail.com:993`). There is no fallback to the `SMTP_*` variables of ElektoMailPosh: a mailbox opened with credentials meant for sending, or for another mailbox, is a mistake better reported than made. While an account is in use (`-Account` or the default account), the `IMAP_*` variables are ignored.
- Authentication by app password (PLAIN). OAuth2 (XOAUTH2) comes later, when a Microsoft 365 mailbox needs it.
- Always TLS (implicit on 993, STARTTLS required otherwise), never MailKit's `Auto`, which falls back to plain text. The account setting `NoTls` (`Set-ImapAccount -NoTls`, or `IMAP_NO_TLS` without accounts) turns it off, documented as meant for tests (smtp4dev has no TLS on IMAP). The tests use that same public setting, so there is no test-only code path: a tool for power users gets public, documented settings, not hidden test hooks nor restrictions for the user's own good.
- A public `SkipCertificateCheck`, as in `Invoke-WebRequest`: accepts a certificate that does not validate, for servers with a certificate of their own and for the TLS tests. Needed because smtp4dev has no TLS on IMAP and MailKitLite never consults `ServicePointManager`, so the test process cannot make the module accept a certificate otherwise.
- `NoTls` and `SkipCertificateCheck` are settings of the account (since #8; #7 had made them switches of each command), with `IMAP_NO_TLS` and `IMAP_SKIP_CERTIFICATE_CHECK` without accounts, read like `IMAP_ALLOW_WRITE`: they are of the server, and as switches a pipeline would repeat them in each command (`Get-ImapMessage | Read-ImapMessage`). The commands have no such switches; `Resolve-ImapConfiguration` returns them in the settings, and the connection reads them from there.
- Gmail translates the names of special folders, so `-Folder` takes `Inbox`, `Sent`, `All`, `Drafts`, `Trash` or `Junk`, resolved by SPECIAL-USE/XLIST, besides a folder name.
- Standard IMAP first: Gmail and Workspace are the first users and their quirks are supported, but nothing may depend on what only Gmail has. A Gmail extension is used when the server announces it (X-GM-EXT-1), never required; `-Query` is the exception, documented as Gmail only.
- Big tools for building and testing are fine while CI stays free; what ships must stay light.

## Policies

Designed before the read commands and implemented with them, in `Private/Policies.ps1`.

- For agents: a policy prevents accidents, such as an agent reading the full message it should not, and makes the owner's intent explicit. It is not a protection against the agent, which is not an adversary. The documentation says plainly what a policy does not do: metadata (headers, subject, labels, attachment names and sizes) is always readable, so whoever needs it hidden should not give an agent this tool; an agent with a shell, as the same user, can change the policy, edit accounts.json or read the stored password; senders can be forged; there are no rules for the thousands of services that send codes and password resets; mail is untrusted input (prompt injection), and the care is to keep such things out of the mailbox in the first place.
- A policy is a named object, separate from the accounts (`Policies` in accounts.json), associated with an account by its setting `Policy`; several accounts may share one. An account without a policy allows all reading (writing still needs `AllowWrite`).
- Format and commands: `Set-ImapPolicy <name> -DenyFolders ... -MaxMessageSize 25MB` (only the settings given change; an empty list or value removes one, 0 removes a limit), `Get-ImapPolicy` (with the accounts that follow each), `Remove-ImapPolicy` (refuses, `PolicyInUse`, a policy an account follows), `Set-ImapAccount -Policy <name>` (`''` removes; an unknown policy is refused). Without accounts, `IMAP_POLICY` names a policy of accounts.json, ignored while an account is in use. Everything is a PowerShell wildcard pattern, matched by `Test-Wildcard` (see Text and culture): senders need an `@` (`*@example.com`; a sender without one would match nothing, letting a deny list through), folders as `-Folder` takes them (special uses included, through `Select-ImapFolder`), and attachments are a MIME type when they have a `/` (`image/*`) and a file name otherwise (`*.pdf`). Refused: a pattern that is not valid (`report[12`), which would fail only when applied, and a bare extension without wildcards (`.pdf`, `pdf`), which would match a file of that very name only (`*.pdf` matches `.pdf` too); `.env.*`, `.config.json` and `report[12]` are fine (Copilot on #10). Sizes in bytes. In the file, an empty list is refused rather than guessed (allow none, or no rule?). An account whose policy does not exist (a file edited by hand) reads nothing: `Resolve-ImapConfiguration` reports `PolicyNotFound`, while the file stays readable so the account can be fixed. `Set-ImapPolicy` warns when an allow list of senders has no `TrustAuthenticationResults`, since it then passes no sender. Settings carry the resolved policy as `Policy` (its rules plus `Name`, or `$null`).
- What a policy governs: folders whose messages may not be read nor changed; senders (addresses or domains) whose full message may be read (allow list) or not (deny list); senders whose attachments may be saved; attachments allowed and denied by MIME type and by file name; a time window, so old mail is not searched; limits per command. An allow list, when present, denies what it does not name; a deny list wins.
- One check for every path (list, search, read, save, later threads), made on the headers before the body or an attachment is fetched. A command parameter only narrows the policy, never widens it.
- The agent sees each message's metadata, not its body, and knows that it is withheld by the policy (a property of the message and a clear refusal from `Read-ImapMessage`), never a silent omission: knowing why something that exists cannot be downloaded is part of the use.
- Applied by `Get-ImapMessage`: every message is listed with its metadata, and the property `Withheld` says why its body is withheld, or is `$null`; `Read-ImapMessage` calls the same check before fetching the body. `MaxAgeDays` goes into the SEARCH (an earlier `-Since` is narrowed to it); `MaxMessages` counts per account over the whole command, lowering `-First`, with a warning saying how many the policy left out (none when `-First` cuts). On Gmail a message is also withheld when one of its labels is a denied folder (system labels such as `\Inbox` and `\Sent` stand for their special-use folders): otherwise All Mail (`-Query`) or the inbox would leak what `DenyFolders` withholds. Gmail marks no folder `\Important` in its LIST (measured on a real Gmail, 2026-11-07: `LIST (SPECIAL-USE)` marks Flagged, Sent, Trash, Drafts, Junk and All; XLIST would mark it, but MailKit uses SPECIAL-USE), so the label `\Important` stands for no folder: a special use named in `DenyFolders` withholds the messages with its system label whether a folder is marked with it or not (`DeniedUses` in `Get-PolicyFolderSet`). And Gmail leaves the label of the folder open out of the X-GM-LABELS of its messages (measured: no `\Inbox` read from INBOX, no label read from its folder, no `\Important` from the folder of important messages, while `SEARCH X-GM-LABELS` finds them all), so in the folder of such a label, which nothing tells apart, the label shows on no message: in a folder without a special use, the messages with it are found by one `SEARCH X-GM-LABELS` per folder in the session (`Get-LabelledUidSet`, only on a server with X-GM-EXT-1, which another would refuse; a search that fails withholds). Checked on a real Gmail: every recent message of that folder withheld by `DenyFolders Important`, which the label alone missed. The full name `[Gmail]/Important` withholds only what is read from that folder; `-Folder Important` is `FolderNotFound` there. The fake Gmail lists that folder unmarked and leaves the label of the folder open out, as Gmail does.
- Sender rules hold only for an authenticated sender: the policy setting `TrustAuthenticationResults` names the receiving server (`mx.google.com` on Gmail), and a sender is authenticated when the topmost `Authentication-Results` header, from that server, has `dmarc=pass` with `header.from` the domain of the From or a parent of it (`Test-WithinDomain`: Gmail names the domain whose DMARC record it applied, `header.from=example.com` for a sender at `news.example.com`, with `p=REJECT sp=REJECT`; measured on a real Gmail, 2026-11-07, where the exact match left out every sender of a subdomain; an allow list still matches the address, so `*@*.example.com` names the subdomains), or, when it has no DMARC result at all, a DKIM pass of that very domain (`header.d`, or the domain of `header.i`), which is how DMARC takes an aligned signature (`Test-DomainAuthenticated`; a DMARC result, when present, decides; MimeKitLite parses the header). Only the topmost header counts, and a message with more than one From is not authenticated. Allow lists of senders match only authenticated senders, so a domain with neither, or a policy without `TrustAuthenticationResults`, passes none; deny lists match the From as written, and also the Sender, the Reply-To and every X-Original-From (`Get-MessageAddress`), since an address there only withholds more. Messages in the special Sent folder count as authenticated, and the docs say so: the user's own messages have no such header. Tests send messages to smtp4dev with the headers they need (it adds none).
- Limits per command, so nothing large is downloaded by accident, attachments above all: how many messages a command handles, and sizes (of a message, of an attachment), checked on the metadata (RFC822.SIZE, BODYSTRUCTURE) before anything is downloaded.
- Never fetch remote content (images) nor follow links; reading by IMAP sends no read receipt.
- No hiding by recipient (alias): metadata is what makes the tool useful.
- No redaction of the text (CPF, card numbers): the tool is for getting information. Taking out what drives a terminal or hides text (`Format-ShownText`, see Text and culture) is no redaction: no reader sees it.
- Seen on real mail (a Google Workspace inbox, structure and headers only): a client's message (corporate Outlook, Exchange Online) relayed by a Google Group of the mailbox's own domain. Google Groups rewrites the From ("'Name' via Group" <group@example.com>) and keeps the original in Reply-To, X-Original-From and X-Original-Sender. The topmost Authentication-Results, from mx.google.com, has dkim=pass for the domain of the group, arc=pass and spf=pass, but no dmarc result, so `Test-AuthenticatedSender` does not authenticate it; Google records the original sender's results in X-Original-Authentication-Results (`mx.google.com; ... dmarc=pass (p=QUARANTINE sp=QUARANTINE dis=NONE) header.from=client.example`), which confirms the format assumed for Gmail's dmarc results. So, before the relays below, under `AllowReadFrom '*@client.example'` every message through a group was withheld, and `DenyReadFrom` on a sender missed a message a group relays, since its From is the group. The same message: nine images pasted by Outlook, all `image.png` with GUID Content-IDs, inline in a multipart/related (two of them signature logos, same size, created months before); Content-Disposition carries size, creation-date and modification-date (sender-declared, so `MaxAttachmentSize` keeps the server's size); the zip came as `application/x-zip-compressed`, which MimeKit maps to no extension (so a pattern by name, `*.zip`, is surer than one by type); the HTML also points to remote signature images, never fetched. `X-MS-TNEF-Correlator` was empty and there was no winmail.dat; MimeKitLite has `MimeKit.Tnef.TnefPart.ExtractAttachments`, should a winmail.dat ever need opening.
- Relays, after that message: the deny lists and the DKIM pass above, and the policy setting `UseXOriginalFrom`, a switch of the policy rather than of a command, since a command parameter may only narrow the policy, and off by default, since it takes some understanding of headers. With it, allow lists judge the topmost X-Original-From (`Get-RelayedSender`) only when the From is of the domain of the mailbox's user (a group of its own), authenticated as above, and the `arc=pass` comment of the trusted Authentication-Results (`i=4 ... dmarc=pass fromdomain=client.example`, which MimeKit gives as `ResultComment`, sealed by the group when it took the message, read ignoring case as RFC 8601 says) names the domain of X-Original-From, or a parent of it, as `header.from` may (not seen in an ARC comment on real mail: taken alike). X-Original-Authentication-Results is not trusted: any sender can write it, and an authenticated relay of another domain with forged X-Original-* headers would otherwise pass. The Withheld reason says which condition a message missed. It is meant for Google Workspace, whose domain is the user's own: on a gmail.com mailbox every Gmail user is of the mailbox's domain, so only the ARC check tells a group's message from a forged one (seen on the real Gmail, 2026-11-07, see Testing against servers); the README says so, with no list of public domains in the code (decided with JP).
- Mail from inside the domain: Google Workspace delivers the mail between users of the same domain with no Authentication-Results (measured on a Workspace mailbox, 2026-11-09), so no colleague is authenticated, and an allow list withholds them. The policy setting `TrustSameDomain` (decided with JP: a switch of the policy, off by default, as a server that does not stamp every message from outside, Microsoft 365 perhaps, would let a forged colleague through) takes for authenticated a sender of the domain of the mailbox's user whose message carries no Authentication-Results of the server of `TrustAuthenticationResults`, anywhere (`Test-InsideSender`): Google stamps every message from outside, a forged one included, and removes one that claims its name (measured), so a forged colleague comes with results, which then decide as for any sender. Its domain is the very domain of the user, not a parent nor a child; a header that cannot be read counts as one of that server. Without the switch, the reason of a withheld colleague says that `TrustSameDomain` would take it.

## The public commands

- Accounts: `Set-ImapAccount`, `Get-ImapAccount`, `Remove-ImapAccount` (wildcards and pipeline, as in ElektoMailPosh), `Test-ImapAccount` (connects, authenticates, shows the capabilities). Policies: `Set-ImapPolicy`, `Get-ImapPolicy`, `Remove-ImapPolicy` (see Policies), applied by the commands that read.
- Commands take the pipeline by property name (Account, Folder, Uid). Each command opens one connection per account (see Connections). An account that fails is a non-terminating error that does not stop the others.
- `Get-ImapFolder`: Account, Folder (the full name, which binds to `-Folder` of the next command), SpecialUse, Count, Unread.
- `Get-ImapMessage`: `-Account` takes several names or wildcards, each object carrying its Account; `-Folder` (default Inbox, or All Mail with `-Query`), `-Since`, `-Unread`, `-From`, `-Subject` (all in the server's SEARCH; `-From` and `-Subject` find part of the text), `-Query` (X-GM-RAW, Gmail only, `QueryNotSupported` elsewhere), `-First` (default 50, per folder; newest first). It returns Account, Folder, Uid, UidValidity, Date (INTERNALDATE, when the server received it: what `-Since` and `MaxAgeDays` filter on, and what the sender cannot forge), From, To, Cc (text, `Name <address>`, at most 100 of a list), Subject (all that the sender writes as `Format-ShownText` shows it), Size, Flags, HasAttachments (by `Get-ImapFilePart`), MessageId, InReplyTo, ThreadId and Labels (on every message, `$null` off Gmail, so all objects have the same shape) and Withheld, with a table view grouped by account and folder (date, sender, subject, marks for unread, attachments and withheld). Tests: smtp4dev for search, filters and policy; the fake Gmail for labels, ThreadId, X-GM-RAW and HasAttachments.
- `Read-ImapMessage`: input from the pipeline of `Get-ImapMessage` (Account, Folder, Uid, UidValidity) or typed; a `UidValidity` that differs from the folder's is `UidValidityChanged`. It fetches only the text part (BODY.PEEK of that part), never the whole message, so attachments are not downloaded. The same policy check first: withheld is the error `MessageWithheld` with the reason, and nothing is fetched; `MaxMessages` counts the messages read per account, with one warning saying how many were left out. `Text` holds the text/plain part, or the HTML as it is when there is none, as `Format-ShownBody` shows it, and `Format` says which (`Text` or `Html`); `-Html` gives the HTML part instead. No HTML conversion (see MimeKitLite above). `-MaxLength` has no default; when it cuts, `Truncated` is `$true`. `Attachments` and `InlineParts` list `Name`, `FileName` (the name `Save-ImapAttachment` gives the file), `ContentType`, `Size` (an upper bound of the decoded size, see `Get-AttachmentSize`) and `Withheld`, from BODYSTRUCTURE, nothing downloaded.
- `Save-ImapAttachment`:
  - Writing: `-Path` is a directory that must exist (thrown otherwise), of the FileSystem provider (a Registry path resolved to a path relative to the process). A file that exists is replaced only with `-Force` (`AttachmentFileExists`), a directory in its place never (told before the fetch: Copilot's third review on #13), nor a read-only file (told before the fetch, by `FileInfo.IsReadOnly`, which on Linux says whether the current user may write the file, measured; Windows refused to replace one, and Linux replaced it), nor a file this command saved, since UIDs are per folder (its second review). Each file is written under a temporary name in the same directory and renamed, so a watcher never sees half a file, in a task (`$script:SaveFileTask`, a delegate compiled from an expression tree: the temporary file opened with CreateNew, then the rename once it takes `$commit`, see Architecture), so that a failure is one `AttachmentWriteFailed` through `Wait-ImapTask` and the file that was there is never returned as if saved (measured before the fix: with `-Force` and the old file open with no sharing, as Excel keeps a workbook, the command returned the old file, and the error came twice in `-ErrorVariable`; a try/catch also gives it twice, and `Move-Item -ErrorAction Ignore` fills no `-ErrorVariable`). The FileInfo comes from `Get-Item -Force`, without which a name that starts with a dot, hidden on Linux, is not found, and falls back to a `FileInfo` when the file is gone at once. Output: the FileInfo, with Account, Folder, Uid, Attachment and Inline. `-WhatIf` fetches no attachment. The checks before the fetch are `Test-FileTarget`, which also holds the final path to `-Path`, whatever the name (`Get-ContainedPath`, `PathOutsideDirectory`: the full path, its directory resolved as the directory of a name surely in it, so that a root or a share is no special case, and its leaf the name itself, which a name with `..`, a separator, a stream on Windows or a dot that Windows drops is not), and the write is `Write-ImapFile`; both are shared with `Save-ImapMessage`, with ErrorIds by kind (`AttachmentFileExists`, `MessageFileExists`). The names are made safe before, so `PathOutsideDirectory` never comes of them: a test gives a name with `..` by a mock of `Get-MessageFileName` and of `Get-AttachmentFileName`.
  - The Mark of the Web, on Windows: the task writes `[ZoneTransfer]`, `ZoneId=3` to the stream `Zone.Identifier` of the temporary file, before the rename, which keeps the stream (measured on NTFS and on ReFS, the volume of the repository), so that the file is never in its place without it. A volume that keeps no streams either refuses it (FAT32 and exFAT take no `:` in a name) or writes it as a file of its own named with the `:` (the share of WSL, `\\wsl.localhost\<distro>`, measured: the first try left `report.pdf.<id>.part:Zone.Identifier` beside the file, `:` mapped to U+F03A; Samba does the same when it maps names). A stream still there once the temporary file is gone is such a file: the task deletes it. Either way the file is saved, and one warning for each directory says why; the task returns that reason (`Task<string>`), so that it is no error. No switch turns the mark off: `Unblock-File`, from the pipeline, takes it off. Tests: `Get-Content -Stream`, and the wrapper `ElektoImapPoshTests.HeldSave.Unmark`, which sends the mark to a stream no volume takes (`:$BITMAP`) or to a file of its own, as those volumes do. The mark written after the rename rather than before is a mutation no test catches, the end being the same; it stays before, so that a watcher never sees the file unmarked.
  - Fetching: a `message/*` part that is not encoded is fetched as the server keeps it (`GetStreamAsync(uid, PartSpecifier)`, `BODY.PEEK[n]`), an .eml byte for byte, since MimeKit, parsing it, wrote the line ends of the platform and nothing for what is not a message. A part that is the whole body of a message has an empty `PartSpecifier`, for which MailKit itself asks `BODY.PEEK[]` (`GetBodyPartQuery`), so the fetch as kept takes `TEXT` for it, or the .eml carried the headers around it (Copilot's sixth review on #13). The decoded size is held to `MaxAttachmentSize` again after the fetch.
  - The file name (`Get-AttachmentFileName`), the same on every platform: never a path (only the last part); composed (NFC, `ConvertTo-ComposedText`: macOS takes a name and its NFD form for one file, so with `-Force` the second replaced the first; a lone surrogate, which `Normalize` refuses with an exception, becomes `_` first); without the characters that only change how it is shown, and with `_` for those Windows refuses and for those that hide, reorder or drive (the classes of `Format-ShownText`: control characters, C1 included, overrides and isolates of direction, the tags of Unicode; the marks of direction, U+061C included, are removed), nor the dots and spaces Windows drops at the end (again after the cut, Copilot on #13); at most 200 bytes of UTF-8 (Linux takes 255 to a name; cut after taking 200 characters at most, since the byte loop took 36 s on a name of 80,000 characters, measured); `_` for the `~` of a name shaped as an 8.3 short name (`REPORT~1.PDF` can stand for another file of the directory, which `-Force` would replace; many volumes keep no short names now, so that test runs only where one does); `_` before a device name (CON, NUL, COM1, COM and LPT with a superscript or any Unicode digit, CONIN$, CONOUT$, also followed by spaces: Project Zero on Windows 8.1 and 10, `COM1  .blah` is COM1; Windows 11 writes `NUL .txt` as a file, measured); and `attachment` plus the extension of its type (MimeKit `MimeTypes.TryGetExtension`) when nothing is left. A name repeated in a message is numbered, attachments first, so an attachment keeps its own name (`image.png`, `image (2).png`, as Gmail names every pasted print `image.png`, so the names are the same on every run; `.env` numbered `.env (2)`; the next number of each name kept, since 2,000 copies took 24 s, measured). `-UniqueName` puts `<Uid>-` before each name. The name the message gives, in `Name` and in messages, goes through `Format-ShownText` (before it, `Format-ShownName` gave control and bidi characters as `?`).
  - Selection: `-Name` matches the name the message gives or the name of the file, `-ContentType` the MIME type the sender declares, both validated by `ValidateScript({ Assert-WildcardPattern $_; $true })` (when the script throws, PowerShell shows its exception and ignores `ErrorMessage`). A message given twice is saved once; the messages seen are kept in each session, not keyed by the user, since two servers may give the same user, folder, UIDVALIDITY and UID (Copilot's sixth review on #13). `Find-ImapFolder` keeps the folders of each name for the session (`Get-ImapMessageByUid` searched them all for each message of a pipeline, 3 ms a message with 500 labels).
  - The policy, per attachment, after the message check (a withheld message is `MessageWithheld`): `AllowAttachmentsFrom` (as `AllowReadFrom`; the user's own messages count as authenticated), `DenyAttachmentTypes` over `AllowAttachmentTypes` (MIME type with "/", else file name), and `MaxAttachmentSize` on `Get-AttachmentSize` (an upper bound of the decoded size from BODYSTRUCTURE: base64 3/4 of Octets), all before the fetch; `AttachmentWithheld` says why. The rules on names take the name the file gets, not the message's (`x.exe.` would be saved as `x.exe`), and the name written too when a number or `-UniqueName` changes it, both having to pass (Copilot on #13: a second `secret.pdf`, written as `secret (2).pdf`, escaped an exact deny), so an exact allow list passes neither `report (2).pdf` nor `12045-report.pdf`.
  - Inline parts: the attachments are the parts with a disposition of attachment and those with a name that are not images, as Apple Mail sends a PDF inline, or a client a CSV (`Get-ImapFilePart`, also behind `HasAttachments`; a named text counts, and a text without a name is the text of the message); `-Inline` also saves the other leaf parts of `BodyParts` that are not text nor message (images pasted or embedded, named as Outlook's `image001.png` or not, as the screenshots clients paste in messages, photos that cameras send, parts without disposition, files without a name, a message whose whole body is an image), opt-in because most messages carry logos and signatures so; `-ContentType` filters by MIME type (`-Inline -ContentType image/*`). `Get-ImapPartList` lists attachments, then inline parts, each in the order of the structure; `Read-ImapMessage` lists them in `InlineParts`, apart from `Attachments`; the same policy rules apply to them as to attachments.
  - Copies: a part whose content (SHA-256) equals one saved before from the same message is not written again, and a file that exists counts, so a rerun gives the same, with a warning that names the file already in the directory (it may be of another message). Only a file written counts (Copilot's fourth review on #13: a failed write kept the copy under another name from being saved), and one that exists only when it can be read (`Get-FileHash -ErrorAction Ignore`, since on a file another program keeps open with no sharing it adds a `FileReadError`, a second error for one refusal, measured). A match by name and size, the first way, dropped another file of the same size (Copilot on #13). Seen on real mail: the mail of a camera (an NVR) forwarded by Gmail carries its snapshot both inline, in a multipart/related, and attached, the same 34,214 bytes; `Read-ImapMessage` lists both parts.
  - The MIME type is read in lower case: a part without parameters keeps the case of the server (Gmail sends BODYSTRUCTURE in upper case), one with parameters comes lowered by MimeKit. MimeKit trims trailing spaces of a file name parameter, not dots.
  - Tests: `Tests/Attachments.Tests.ps1`, against the fake Gmail, which serves several parts per message (a TEXT part needs its line count in BODYSTRUCTURE, or MailKit fails on the NIL after it; the key `Whole` makes a message whose whole body is one part) and one client at a time: a test with two accounts in one command starts a second fake server, and `Set-TestAccount` (`Tests/TestAccounts.ps1`, taking `-SavedEnvironment`) takes a `Port` for an account. The write is held by a wrapper in C# (`ElektoImapPoshTests.HeldSave`) of `$script:SaveFileTask`, in a runspace that `BeginStop` stops (`Start-HeldSave`, which takes the command as a text, since a script block keeps to the runspace it was made in): stopped while it writes, the command ends at once and the file there is kept; stopped once the task renames, the command waits for the task. The task starting just before the `try` rather than inside it is a mutation no test can catch, since PowerShell notices Ctrl+C only at the call inside the `try`; it stays inside so as not to count on that.
- `Save-ImapMessage`, not the normal use of the module (for evidence, a mail client, the headers that tell how a message came):
  - One message whole, as the server keeps it (`GetStreamAsync(uid)`, which MailKit sends as `BODY.PEEK[]`), as an .eml named `<Uid>-<subject>.eml`, or `<Uid>.eml` without one (`Get-MessageFileName`: the subject through `Get-AttachmentFileName`, its slashes as `_` and each run of its tabs and line breaks as a space, since a subject is no path and the rule of attachments, the last part only, made "Invoice 11/2026" a "2026.eml"), written by `Write-ImapFile` as attachments are (the temporary name, the Mark of the Web, Ctrl+C), with Account, Folder and Uid on the FileInfo. `-WhatIf` downloads nothing of the message.
  - One and only one: what comes is kept in `process` and handled in `end` (in a script block of its own, which a step that fails leaves, so that `end` still logs out), so that more than one from the pipeline saves nothing and connects to nothing (`MoreThanOneMessage`). By `-Uid` (a number, not a list) or by `-MessageId` (`Find-ImapMessageById`): the SEARCH (HEADER Message-ID) finds the messages whose Message-ID has the text, ignoring case, narrowed by `MaxAgeDays`; their envelopes alone are then fetched and held to the whole Message-ID, ordinal, given with or without its angle brackets (MailKit gives it without), so that `abc@x` is not `xabc@x`; two that have it save nothing (`MoreThanOneMessage`, naming their UIDs). A search that finds more than `$script:MessageIdCandidates` (100) fetches no envelope and saves nothing: a short text (`gmail.com`) is part of the Message-ID of thousands, and the envelopes are held to it at some 50 us a message (measured). The default folder is the inbox, as for `-Uid`; on Gmail, `-Folder All`.
  - The policy, all before the fetch: `Get-WithheldReason`, then every part of `Get-ImapPartList`, attachments and inline parts alike (what `Save-ImapAttachment -Inline` would save), since the .eml carries them all; the first part withheld says why, with how many more (`MessageWithheld`). `MaxMessageSize` again on the message fetched, as `MaxAttachmentSize` is on an attachment; the parts in the .eml keep the sizes the structure told. `MaxMessages` is not counted: it is 1 at least, and the command handles one message.
  - Tests: `Tests/Attachments.Tests.ps1`, against the fake Gmail, whose `BODY[]` is the message it builds, so the file is compared with its headers and its CRLF.
- `Get-ImapThread` (Gmail only, `ThreadNotSupported` elsewhere, once for each account): the messages of each thread (`UID SEARCH X-GM-THRID`) from All Mail (`Open-NamedImapFolder 'All'`), the oldest first, by UID, as Gmail shows a conversation, each as `Get-ImapMessage` returns it (`ConvertTo-ImapMessage`, with `Withheld` from `Get-WithheldReason`), so they pipe to `Read-ImapMessage` and `Save-ImapAttachment`. `-ThreadId` takes the ThreadId of `Get-ImapMessage` from the pipeline, and `$null` (`[AllowNull()]`), which a message of another server carries, so that the error says why: PowerShell only said that it was null, in an error that `-ErrorVariable` missed (measured). A thread given more than once (by several of its messages) is listed once, by a `HashSet` of the session; one with no message is `ThreadNotFound`, which says when `MaxAgeDays` may be why. `MaxAgeDays` goes into the SEARCH; `MaxMessages` counts per account over the command and keeps the newest of a thread, as `Get-ImapMessage` keeps the newest of a folder, with one warning in `end`. No `-First`: Gmail keeps a conversation to 100 messages. The trash and the spam are not in All Mail, so their messages are not listed. Tests: `Tests/Messages.Tests.ps1`, the fake Gmail, and smtp4dev for `ThreadNotSupported`.

## Testing against servers

- smtp4dev (`dotnet tool install -g Rnwood.Smtp4dev --version 3.15.0`) has an IMAP server. `Tests/Smtp4dev.ps1` starts it for the tests on free ports of the loopback, in memory, with `--nousersettings --allowremoteconnections- --bindaddress=127.0.0.1`, and kills its process tree afterwards (the `.cmd` of the tool starts the server as a child); tests that need it are skipped where it is not installed. CI installs it (a pin Dependabot does not follow, also in `Tests/Container/Containerfile`) and stops when it is missing from the PATH, so those tests never skip there. `--authenticationrequired --user=name=password` makes its LOGIN check the password; without them it takes any. It has an INBOX and a `Sent` folder that it does not mark `\Sent` (good for the fallback of `-Folder Sent` to the folder's name), no LIST-STATUS or SPECIAL-USE, no TLS on IMAP (its test accounts have `NoTls`), and its BODYSTRUCTURE leaves attachments out, so it cannot test HasAttachments. `Send-Smtp4devMessage` delivers a message to its INBOX by SMTP, with the same login. Its STORE takes `+FLAGS` (it does set `\Seen`, so a test can see a message marked as read), ignores `-FLAGS` and answers BAD to `FLAGS`: a flag added cannot be taken back, so a test that marks a message needs a server of its own. A message fetched (BODY.PEEK) from a folder opened read-only stays unread. Its default package listens on every interface with no authentication: keep it bound to the loopback, as the tests do.
- Linux natively (an Arch-based distribution, 2026-11-07): Pester and PSScriptAnalyzer by `Install-PSResource -Scope CurrentUser`, smtp4dev by `dotnet tool install -g` (owned by the user, so it needs no `chmod`); `./Build.ps1` passed with 7 tests skipped, six for Windows and the implicit TLS on port 993. Without `core.autocrlf` there, the working tree keeps LF. With no WSL there, Podman (rootless) plays its part: `Tests/Container/Invoke-ContainerBuild.ps1`, where the user of the container is a subordinate user of the machine with no right over its files, so the repository must be readable by others, and a folder of scripts mounted for an experiment too (the session's scratchpad, mode 700, is not). The machine has the user's real accounts, so the tests of accounts and passwords run in the container.
- Linux on Windows: WSL (Debian) with pwsh 7.6, the .NET SDK 10, Pester 6.2.0 (for all users) and smtp4dev 3.15.0 (`dotnet tool install Rnwood.Smtp4dev --version 3.15.0 --tool-path /opt/smtp4dev`, linked from `/usr/local/bin/smtp4dev`; the package leaves its program executable by root only, so it needs `chmod a+x` on `.../tools/net10.0/linux-x64/Rnwood.Smtp4dev`, again after an update). WSL runs as root by default, which ignores file permissions, so run as an ordinary user: `wsl.exe -u <user> -e pwsh -NoProfile -Command "Invoke-Pester /mnt/<drive>/<path of the repository>/Tests"`, from PowerShell (Git Bash rewrites `/mnt/...` arguments into Windows paths). The tests that need an ordinary user skip themselves as root. Seen from Windows, the share of WSL (`\\wsl.localhost\Debian\tmp\...`) is a volume without streams that takes `:` in a name, where the Mark of the Web was checked by hand (no admin needed, as a volume of FAT32 would be); a shell in WSL did not see that directory in its own `/tmp` (measured), and a file named with `:` there is deleted from Windows by that name, not by the one a listing gives.
- No emulator has the Gmail extensions (X-GM-RAW, X-GM-THRID, X-GM-LABELS, translated folders). `Tests/FakeGmail.ps1` is a fake Gmail server, in a runspace on the loopback like `Start-FakeImapServer`, answering the commands MailKit sends from a list of messages, and keeping the commands it got (tests check the EXAMINE, the X-GM-RAW, the SINCE). Its SEARCH takes X-GM-RAW, X-GM-LABELS, X-GM-THRID, HEADER Message-ID (a part of it, ignoring case, as IMAP searches a header, so that a test of an exact match sees the others a server finds) and SINCE, and ignores any other term; its FETCH leaves the label of the folder open out of X-GM-LABELS, as Gmail does. Its answers follow Google's page (developers.google.com/workspace/gmail/imap/imap-extensions) and the real Gmail transcripts in MailKit's tests (`UnitTests/Net/Imap/Resources/gmail`, read with `gh api repos/jstedfast/MailKit/contents/...`): system labels quoted (`"\Important"`) or as atoms, `[Gmail]` marked `\NonExistent`. It announces less than Gmail (no ESEARCH, LIST-STATUS, CONDSTORE). It proves our reading of those answers, not Gmail's.
- A real Gmail mailbox (2026-11-07, folder names in Portuguese, read under a policy for the agent, by a script in the scratchpad that printed only counts, times and reasons): every command against it, and nothing marked as read. Its `Authentication-Results`, which Copilot also asked about on #11: the topmost from `mx.google.com` on every message of the inbox measured, a few with others below it from the sender's own servers, and none on the sent messages. A message sent to it with forged headers (from another Gmail account, through `smtp.gmail.com`, 2026-11-07) came to the inbox without the `Authentication-Results` that claimed `mx.google.com`, which Gmail removed, as RFC 8601 says a server should do with one that uses its name (seen on Google's own path; from a server outside Google, untested), and with, below Gmail's own and as written, one from `mx.example.net`, the `X-Original-From` and an `X-Original-Authentication-Results` that claimed `mx.google.com`. The module took Gmail's own as the topmost (with a method new to us, `dara=pass header.i=@gmail.com`, which MimeKit parses as any other), authenticated the sender as gmail.com, and refused the forged X-Original-From under `UseXOriginalFrom` at the ARC check alone: the mailbox and the sender being both of gmail.com, the check of a group of the mailbox's own domain passed. Each command connects and logs in in some 2.4 s, and takes 3 to 5 s; `Get-ImapThread` some 1 s a thread (one SEARCH each). Integration tests against a real account, run only locally from environment variables and skipped without them, are still to come, never in the public CI.
- A Google Workspace mailbox with mail migrated from more than a decade back (2026-11-09, read as above, its policy without `MaxAgeDays`, as finding old mail is its use): the migration kept the dates (INTERNALDATE within an hour of the Date of the header), so `-Since` and `older_than:` find old mail; old text decodes, accents included, with no U+FFFD; mail from inside the domain has no Authentication-Results (see Policies, `TrustSameDomain`); most senders of old mail are not authenticated (no DMARC result, and no DKIM signature of their own domain, before DMARC was common), so an allow list withholds most old mail, and its attachments: for a mailbox searched for its history, deny lists fit better; the messages that a Google Group of the domain relayed were taken by `UseXOriginalFrom` but for a few without ARC, the ARC `fromdomain` was in some a parent of the sender's domain (as `header.from` may be, see Relays), and the older ones were not, the group itself not authenticated then (no signature of the domain, no ARC). No detail of the mailbox goes in this file: JP asked for none.
- Where the time goes, measured from Brazil against Google Workspace: starting `pwsh` some 0.2 s, importing the module 0.25 s, connecting (TCP and TLS) 0.6 s, logging in 2.1 s (the slowest step), listing the folders 0.4 s, each round trip some 0.4 s (opening a folder, a search, a fetch); a whole command as an agent runs it, in a process of its own, some 5.5 s; the same work on a connection kept open some 0.9 s, against 4.4 s with a connection of its own. `Read-ImapMessage` takes some 0.9 s a message (two round trips each: its summary, then its text).
- TLS: `Tests/TlsProxy.ps1` (C# by Add-Type, only in the tests) puts implicit TLS or STARTTLS in front of smtp4dev, with a self-signed certificate made in memory and never put in a certificate store; the module accepts it only for an account with `SkipCertificateCheck` (a delegate compiled from an expression tree, since MailKit calls it on a thread with no runspace). On Windows its key sits in the user's key store while the proxy lives (a key only in memory fails the handshake there, tested) and is deleted by `Dispose`. Implicit TLS is used on port 993 only, which an ordinary user cannot open on Linux: that test runs on Windows and is skipped elsewhere.
- A correct BODYSTRUCTURE (attachments) in CI would need GreenMail or Dovecot as a service container, not yet evaluated.

## Workflow

- Claude asks before each commit, each push and each merge, and before anything else that others see (a comment, a review request, a release).
- One piece of work at a time, in a branch and a pull request (`feat/...`, `fix/...`, `docs/...`), merged with a merge commit; the branches stay on GitHub. Related items of the plan go together in one larger pull request, rather than one each (decided with JP on 2026-11-06, after a session of many small ones). Work that must outlive a machine goes to GitHub as a branch, not into a stash.
- Copilot is not asked to review pull requests, since each review is billed to whoever requests it, and none comes on its own any more (JP, 2026-11-06: before, a setting of the account that opened a pull request requested one, which came minutes after the CI could finish), so a pull request is not held for one. Should one come (a `review_requested` for Copilot in `gh api repos/<owner>/<repo>/issues/<n>/timeline`), address what is pertinent in the same pull request, and reply in each thread how it was resolved, or why it was declined (in a comment of the pull request when its review opened no thread).
- Once a pull request is open and its CI running, JP is offered the auto-merge of the Claude app for it (a merge commit, the branch kept), as the way to have it merged once the CI is green: the app does not let a session poll the CI, and its Auto-fix wakes a session for a failed check, a conflict or a review comment, never for a green CI. Turning it on is JP's approval of that merge, and only of that one; when JP merges by hand instead, the state is checked once, when JP says the CI passed.
- When GitHub takes the push of a branch but leaves its pull request on the old head, with no CI run (an incident with Actions, 2026-11-05, on #13), an empty commit may not move it either; closing and reopening the pull request did (`gh pr close`, never with `--delete-branch`, then `gh pr reopen`), and ran the CI. Reviews, threads, comments and the description were the same before and after (compared from a copy taken first).
- Commit messages as in ElektoMailPosh: `feat:`, `fix:`, `ci:`, `docs:`, `test:`, `deps:`, with the new version at the end when it changes (`...; 0.1.1`).
- A release: first a round of review in Claude Code with Fable, then the version in the manifest, its `## <version>` section in `ReleaseNotes`, and the tag `v<version>`, which runs `publish.yml` (build with `-ExpectedVersion`, PowerShell Gallery, GitHub release with the zip).
